# A股晚间复盘(收盘后、当晚)

## 适用边界(Scope)

本skill遵守 `../../../references/boundaries.md` 的全部共享边界，正文不再逐条复述。以下仅列本skill特有边界：

- **唯一全量跑技术引擎的时段**:引擎调用方法、JSON字段口径、四维卡片写法、对称条件式情景、降级规则已内联至本 skill 第0步与第5步,自洽执行。
- **取数计划表 gate 自洽**:gate 表格格式与约束已内联至本 skill 启动前章节(配置预检由 `review-orchestrator` 完成)。
- **这是"收盘后信息汇总与衔接",不是"盘后操作建议"**:目标是让用户当晚掌握"今天A股全天/同时段亚太怎么样、白天有哪些相关消息",不给"今晚/明天该买该卖"的结论。
- **亚太与A股的联动/背离只客观陈述**,不据此预测次日方向。
- **白天消息窗口**:覆盖"今晨早间推送之后 → 今晚",与次日 `ashare-morning-brief` 的隔夜窗口首尾相接、合成完整24小时不留缝。
- **Tier 3 事件走队列**:发现 Tier 3 级白天事件时,产出更新建议追加至 `../../../data/macro_updates_queue.json`(协议见 `../../../references/tier3-event-handling.md`),不直接写 `macro_context.json`。

## 复盘内容与执行步骤

> 数据源配置预检(读 `data-source-config.json` + 轻量校验 + 失效时重编排)由 `review-orchestrator` 在调用本技能前完成,本技能直接复用上下文中已有的配置。**取数过程中记录每类数据实际使用的工具(primary 还是 fallback),供末尾"数据来源"小节使用。**

### 启动前必须声明的取数计划表(gate,未完成不得进入第0步)

本skill涉及的数据桶清单(逐桶查配置 `routing`):

- `cn_equity_quote` — A股当日全天行情/资金流向/涨跌停情绪
- `hk_us_equity` — 亚太市场(港股恒指等)收盘行情
- `overseas_uncovered` — Wind不覆盖的亚太市场(日股/韩股)收盘行情,仅采信定性
- `news_policy` — 白天消息面(国内政策/行业/公司/国际事件)
- `announcement_doc` — 持仓/自选股相关公告
- `cn_tech_daily` — 第0步技术引擎算指标所需日线

按下表输出取数计划表后才允许进入第0步:

| 数据桶 | 配置 primary(tool_id) | 配置 fallbacks(tool_id 列表) | 本次将调用(tool_id) | 调用方式(取自配置 primary.invoke) | 参数提示(取自配置 primary.param_hint) |
|---|---|---|---|---|---|
| <桶名> | <从配置读> | <从配置读> | <从配置读> | <从配置读> | <从配置读> |

约束:
- 表中工具相关单元格**逐字来自配置 `routing[桶]` 与 `tools[]`**,不得自行填写工具名或编造调用方式——本 skill 不写任何工具名,工具名只在运行时从配置流入。
- 若某桶 `primary.must_try_before_fallback == true`,取数时**必须先实际调用 primary 并记录返回**(成功/无结果/失败+error.code)后才能走 fallback,不允许跳过 primary。
- `news_policy` 桶要求"多工具组合交叉印证,不允许只用单一 web_search"——表中"本次将调用"必须是 primary 工具;primary 失败退化为"仅 web_search"时须标注失败原因并在报告注明"未经专业资讯源交叉核对"。
- 取数过程中 primary 失败走 fallback,在表中标注失败原因(error.code);报告末尾"数据来源"表必须与此计划表逐桶一致。

### 0. 技术引擎全量运行(盘后第一步,数据落 `output/_tech_cache/`)

晚间是数据最全、最宽裕的时段,先把技术引擎全量跑一遍,产出的均线/支撑压力位构成一组"技术参考位",供次日早间/盘中承接。**本 skill 已内联引擎调用方法、字段口径与降级规则,自洽执行。**

**引擎脚本**:`.claude/skills/ashare-technical-analysis/scripts/compute_indicators.py`,从项目根目录运行,输出落 `output/_tech_cache/`(用完即弃,不污染最终报告目录)。

**取数**:读 `data-source-config.json` 按 `cn_tech_daily` 桶路由择源(专业金融MCP → 本地已安装Python行情包 → 联网搜索仅采信定性),产出标准化日线 CSV(必需列 `date`/`open`/`high`/`low`/`close`/`volume`,前复权,按 date 升序,回溯≥250交易日)。失败按下方降级规则处理,绝不编造数字。

**算指标**(取得 CSV 后;资产类型由是否传 `--benchmark-csv` 区分——指数/ETF 不传,个股传沪深300基准):
1. **大盘四大指数**:对上证(000001)、深证成指(399001)、创业板指(399006)、科创50(000688)各跑一遍(不取基准、不算相对强弱):
   ```bash
   python .claude/skills/ashare-technical-analysis/scripts/compute_indicators.py \
     --csv output/_tech_cache/000001_daily.csv --out-json output/_tech_cache/000001_ind.json
   ```
2. **持仓 + 自选股**:对 `positions`/`watchlist` 每只标的跑一遍——个股传沪深300基准算相对强弱,ETF(如 159558)不取基准:
   ```bash
   python .claude/skills/ashare-technical-analysis/scripts/compute_indicators.py \
     --csv output/_tech_cache/000002_daily.csv \
     --benchmark-csv output/_tech_cache/benchmark_000300.csv \
     --out-json output/_tech_cache/000002_ind.json
   ```
   `--benchmark-csv` 传沪深300基准 CSV(只需 `date`/`close`),用于相对强弱维度;缺则跳过该维度。ETF 命令同指数(去掉 `--benchmark-csv` 即可)。
3. **降级**(红线:宁可缺维度,绝不编数字):
   - 专业金融MCP不可用/额度不足 → 降级本地Python行情包取 CSV,引擎照常跑,技术面注明"本地脚本计算(MCP不可用)"。
   - 专业MCP与本地行情包均失败 → 技术深度整体降级为定性描述(近期偏强/偏弱/震荡),不给任何指标数值/均线价位/金叉死叉,显著位置写明"技术引擎不可用,本次为定性判断"。
   - 某标的取数失败/历史不足60日(次新/停牌) → 跳过该标的指标部分,标注"数据不足,技术面跳过",其余维度正常写。
   - 基准指数缺失 → `relative_strength` 为 null,跳过 alpha 维度并说明,其余照常。
   - CSV 列名不符契约 → 降级定性,不硬编数字。

**引擎输出 JSON 关键字段**(用于写第1步大盘技术面与第5步四维卡片,完整口径见 `ashare-technical-analysis/references/indicators_guide.md`):
- `latest`:最新交易日各指标——`close`/`pct_chg`、`ma5/10/20/60/120/250`、`macd_dif/dea/hist`、`rsi6/12/24`、`kdj_k/d/j`、`boll_upper/mid/lower/pctb/bandwidth`、`atr14`、`adx14`/`plus_di14`/`minus_di14`、`vol_ratio`(量比)、`bias20`(乖离率)、`obv_trend_20d`。
- `signals`:`ma5_ma20`/`ma20_ma60`/`macd_dif_dea`/`kdj_k_d`(golden_cross/death_cross/none)、`ma_arrangement`(bullish_aligned多头/bearish_aligned空头/mixed)、`price_vs_ma250`(above/below)、`macd_divergence`/`rsi_divergence`(顶背离bearish/底背离bullish)。
- `key_levels`:`support`/`resistance` 各含 `level`(价位)、`touches`(验证次数)、可能的 `note`。
- `relative_strength`:`alpha_20d`/`alpha_60d`(相对沪深300超额收益,正=跑赢);指数或基准缺失时为 null。
- `recent_series`:最近20日精简序列(close/pct_chg/volume/ma20/ma60/rsi12/macd_dif/dea),用于描述近期走势节奏。

读 ADX 判信号可信度:`adx14`<20 多为震荡市,金叉死叉、均线穿越可靠性低,文字要点明"当前趋势强度弱、信号需打折"。技术读数只用于"客观状态描述",写法见下方第1块、第5块。

### 1. A股当日全天复盘(优先级最高)
- 主要指数收盘表现(上证、深证、创业板、北证等)及涨跌幅
- 成交额、北向/南向资金当日净流向(只需当日数据本身,中长期趋势交给宏观记忆)
- 领涨/领跌板块、涨跌停家数等市场情绪指标
- **大盘技术面(承接第0步指数引擎结果)**:四大指数各自的均线排列(多头/空头/纠缠)、价格相对 MA20/MA60/MA250 的位置、ADX 趋势强度(<20震荡、>40强趋势)、量价是否健康;指数间分化(权重蓝筹 vs 成长)揭示市场风格偏向。一句话概括每个指数处在"健康上行/高位震荡/趋势走弱/底部修复"哪个状态,并给一条以关键均线/整数关口为锚的**对称条件式情景**(句式见第5步卡片模板),不写涨跌概率。
- 交叉核对持仓/自选股记录:今日是否有相关标的公告或异动

### 2. 亚太市场辅助
- 日经、恒指、韩股(KOSPI)等当日收盘表现——与A股处于同一交易时段,当晚已是完整收盘数据
- 与A股当日的联动或背离,仅客观陈述,不据此预测次日方向(海外完整的隔夜行情由次日早间消息推送处理)

### 3. 白天消息面整理
- **时间窗口**:覆盖"今晨早间消息推送之后 → 今晚复盘时",承接早间消息推送的隔夜窗口,避免两次复盘之间出现信息盲区
- **范围限定**:只收录与市场整体、宏观环境或持仓/自选股所属行业相关的信息,客观陈述,不做解读延伸,不是当日所有新闻的流水账
- **分类整理**(便于快速扫读,也便于与 `ashare-macro-context` 维度框架对应):按"国内政策与监管"/"行业与产业动态"/"公司层面"/"国际重大事件(白天如有)"分组摘要,而不是按时间顺序罗列 (完整分类标准见 `../../../references/message-classification.md`)
- **与持仓/自选股的关联标注**:整理时标注哪些消息与已有持仓/自选股直接相关,作为"隔夜需观察事项"的来源依据之一
- 判断是否有 Tier 3 级别的新宏观事件,产出更新建议追加至 `data/macro_updates_queue.json`（队列协议详见 `../../../references/tier3-event-handling.md`）,并注明建议的类别代码(如 A_政治与政策、J_资本市场制度政策等)

### 4. 板块轮动持续性(承接领涨领跌排名)
- **轮动方向**:今日强势板块相对昨日/本周是延续还是切换,资金是在同一主线内扩散还是在不同主线间跳
- **持续性定性**:领涨板块是"放量+资金净流入+龙头连板"(持续性强)还是"缩量+资金流出+冲高回落"(一日游嫌疑)——用量价资金三者是否共振来定性,**不打概率**
- **持仓板块定位**:用户持仓/自选所属板块处在轮动的什么位置(主线/补涨/退潮),决定个股是顺风还是逆风

### 短期机会发掘(委托给 ashare-opportunity-discovery,位于第4步与第5步之间)
- 在第4步板块轮动持续性判断完成后、第5步四维卡片之前,调用 `Skill("ashare-opportunity-discovery", args="scope=short_term")` 对今日全天出现的短期催化剂/事件驱动机会进行发掘
- 本skill第1步(A股全天复盘)、第3步(白天消息面整理)、第4步(板块轮动持续性)的产出作为机会发掘的扫描素材
- 将发掘结果填入下方输出格式的"短期机会发掘"栏
- 发掘逻辑(催化剂框架/过滤规则/输出格式)详见该skill,此处只做调用和嵌入,不重复其逻辑

### 5. 持仓/自选股四维深度卡片
对每只持仓/自选股产出一张"四维深度卡片",这是晚间复盘技术深度的主战场。短期机会由 `ashare-opportunity-discovery` 独立发掘并分栏呈现(见下方输出格式),与持仓卡片口径不混用:
- **技术面**:用第0步引擎结果做"客观状态描述"——均线排列、MACD/KDJ/RSI 位置、bias20 乖离、ADX 趋势强度,翻译成"当前处在什么技术状态"(如"趋势健康上行、短期略过热"),不甩裸数字
- **资金面**:主力近期净流入/流出、OBV 趋势
- **消息面**:仅与该股/行业相关的重点(无则写"今日无直接相关消息"),不做泛新闻流水账
- **相对强弱(alpha vs beta)**:用 `relative_strength.alpha_20d/60d` 说明今日异动是个股 alpha 还是跟随大盘 beta
- **对称条件式情景**:一条"若…则…/若…则…"两个方向都列出的情景(以参考位为锚,标注"参考位非下单指令")
- **技术位参考**:现价距关键支撑/压力位还有多远(来自引擎计算的 key_levels 和均线位),均为参考位非下单指令

卡片完整写法与句式(本 skill 内联):

```
#### [代码 名称] ｜ 今日 ±X.XX%(板块 ±Y%,沪深300 ±Z%)
- 技术面:站上 MA5/10/20、MA 多头排列、MACD 在零轴上方金叉延续;
  RSI12=XX(未超买/接近超买)、bias20=+X%(乖离合理/偏大)、ADX=XX(趋势强度中等)。
  → 当前处于「趋势健康上行、短期略有过热」的状态。
- 资金面:主力近X日净流入/流出 …;OBV 20日趋势 上升/走平。
- 消息面:(仅与该股/行业相关的重点,1-2条;无则写"今日无直接相关消息")
- 相对强弱:alpha_20d=+X%(跑赢/跑输沪深300)→ 今日上涨更多是个股 alpha / 跟随大盘 beta。
- 条件式情景(对称):若放量站稳 MA20(约 A 元一带)则上行趋势延续得到确认;
  若跌破 MA20 且 MACD 死叉则需警惕转入回调。(A 为参考位,非下单指令)
- 技术位参考:现价 P,下方最近支撑约 XXX(距 P −X%),上方最近压力约 XXX(距 P +X%)。
  均为参考位,非下单指令。
```

对称条件式情景句式库(二选一,禁止只写一边):
- "若放量站稳 MAxx(约 A)则上行趋势延续得到确认;若缩量跌破则需警惕假突破。"
- "若回踩支撑 B 一带获支撑企稳则中期结构未破;若有效跌破 B 则中期趋势转弱信号。"
- "若 MACD 在零轴上方再度金叉则多头动能恢复;若死叉下穿零轴则动能转弱。"
- "若周线站稳 MA60 则中期趋势修复确认;若失守 MA120 则需复查持仓基本面。"

禁止句式:含"明日大概率""上涨概率 XX%""建议在 XX 元买入/卖出""目标看到 XX 元"的单边预测或下单指令。要点:技术面落"状态描述",情景两个方向都写,绝不写"明日买/卖 XX 元"。

### 6. 衔接与承接
- **产出隔夜需观察事项**:把今晚需要跟进隔夜进展的标的/主题列出,交棒给次日 `ashare-morning-brief`(它会核对这些事项的隔夜进展);**一并交棒第0步算出的技术参考位**(各持仓的支撑/压力位),供次日早间承接
- **中长期持仓如遇白天重大消息**:明确写"已标记观察,不建议盘后临时操作",而不是给出操作倾向

## 输出格式

按以下结构输出,保持简洁,每条一两句话:

```
## 晚间复盘 [日期]

### 今日A股全天回顾
- 指数表现 / 资金流向 / 领涨领跌板块 / 涨跌停情绪
- 大盘技术面:四大指数均线排列 / 相对MA20/60/250位置 / ADX趋势强度 / 量价 / 风格分化
  → 每个指数处在「健康上行/高位震荡/趋势走弱/底部修复」哪个状态 + 一条对称条件式情景
- 持仓与自选股相关提示(如有)

### 亚太市场(辅助)
```
