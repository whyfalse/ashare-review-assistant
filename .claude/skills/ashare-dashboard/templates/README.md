# 看板规格文档契约

本文件夹存放看板规格文档(*.md)。每个规格文档是一份**指导性描述**,用文字规定某个看板的架构、模块、组件、样式与缺失处理规则——不提供现成 HTML 骨架,生成时由 `ashare-dashboard` skill 按规格描述 + `SKILL.md` 的「共享设计系统」自行构建 HTML 结构。本 skill **不预设报告类型、不内置"类型→规格"映射表**,而是扫描本文件夹下实际存在的规格文档,结合用户提示词与引用内容**动态匹配**。因此每个规格必须**自描述**自己面向什么数据/报告,供 skill 匹配。

> 本 README 是规格文档契约说明,不是规格本身。规格 md 文件由你逐个创建,放在本文件夹即可。**所有规格文档统一面向移动端竖屏阅读设计**——手机单栏、首屏即结论、深色高对比、触摸友好。共享的配色/字体/移动端规格/比例条规则见 `../SKILL.md` 的「共享设计系统」,本文件只规定规格文档本身的写法。

## 规格文档自描述(必需)

每个规格 md 文件在文件首部用 YAML frontmatter 声明元信息,供 skill 读取匹配:

```markdown
---
name: 晚间复盘看板
match: 晚间复盘,收盘复盘,盘后复盘
target: A股收盘后晚间复盘报告
data: 指数表现,领涨领跌板块,资金面,持仓四维卡片,对称情景,消息面,观察清单
---
```

字段说明:
- `name`:规格展示名。
- `match`:匹配关键词,逗号分隔——用户提示词或引用内容命中时倾向选本规格。
- `target`:本规格面向的数据/报告类型,一句话说明。
- `data`:本规格期望渲染的数据单元,逗号分隔。

> 文件名**自由命名**(如 `evening_review.md`、`周复盘.md`),skill 按 frontmatter 匹配、**不按文件名查表**。无 frontmatter 时 skill 会退而读正文标题与结构推断用途,但匹配不可靠,建议每个规格都写 frontmatter。

## 每个规格 md 文件必须规定的内容

规格正文用文字描述以下四块。**不要贴大段 HTML/CSS 代码**——HTML 结构由 skill 生成时按描述构建,样式复用 `../SKILL.md` 的「共享设计系统」。规格只写"看板长什么样、每个模块怎么呈现、缺失怎么办、本看板有没有额外的样式"。

### 1. 面向报告

一段话说明本规格面向哪个 skill 产出的什么报告,数据源大致包含什么。让生成时的 skill 一眼明白"这份规格是用来渲染哪类内容的"。

### 2. 看板整体架构

从上到下列出看板的分区/卡片顺序,每个区一句话说明用途。说明:
- 首屏放什么(手机竖屏打开即见的核心结论 / 总览数字);
- 纪律措辞位在哪些位置预留——参考位"非下单指令"、对称情景双向、短期机会与中长期持仓分栏、风险提示与免责声明等,标明在哪个模块/位置预留。

### 3. 模块细节

逐模块列出:
- **对应数据**:对应数据源的哪个章节 / 表格 / 字段;
- **展示形式**:数字大字 / 表格 / 横向条形 / 迷你K线 / 标签徽章 / 文字段落 / 卡片列表 / details 折叠 等;
- **数据缺失处理**:该模块某项数据缺失时显示什么(占位符"—" / 灰显 / "数据缺失"标注 / 整块降级 / 整块隐藏);
- **特殊说明**(可选):该模块特有的纪律、口径或邮件兼容注意事项。

### 4. 本看板额外样式与比例条规则

只写本看板**额外**或**偏离**共享设计系统的部分(如风险体检的四档风险专用色、独有断点)。共享配色/字体/移动端规格/比例条三规则一律引用 `../SKILL.md`「共享设计系统」,不在规格里重复贴变量定义。

若本看板用到比例条/横向条形/热力条等需要生成时预算宽度的组件,逐个标注用哪条规则(规则名与适用对象如下,公式定义见 `../SKILL.md`「共享设计系统」比例条三规则):
- **分段比例**:涨跌家数三段等;
- **中心零轴半幅**:资金分流条、指数周涨跌分化条等;
- **单向归一**:板块涨跌条、行业占比条等;
- **离散填色**(非比例类):按当前等级在生成时内联 class(如六层热力条四段)。

若本看板无比例条(如早间消息推送看板不含 A 股当日行情),显式注明"本看板无比例条"。

### 5. 特色纪律与口径

本看板特有的纪律措辞或口径声明。例如:
- 盘中复盘的"盘中快照非收盘数据"警示贯穿全篇;
- 早间推送的"隔夜外盘+消息面"口径(不含 A 股当日行情、技术参考位承接昨晚晚间复盘);
- 周复盘的"跨日中期视角"声明、VIX 定性推断标注、未结事项清算纪律;
- 风险体检的"红旗优先于加权平均""风险等级为定性判断非精确预测""分层矛盾明说"等。

这些纪律措辞在生成时原样保留,不得为版面精简而删除。

## 约定

- 规格文档里的数字 / 文字 / 标的名称为**示意占位**,仅用于说明模块长什么样;skill 生成时用数据源真实数据替换。规格中所有占位数据必须使用虚构的示例名称(如"示例科技""示例股份""示例行业ETF""示例公司甲""示例领涨股A"等),占位代码使用通用伪码(如"000001""000002""159001"等)。规格注释中提及标的时也应使用泛称(如"持仓股A""自选股B"),不在规格层面绑定任何具体标的。
- 规格文档**移动端优先**:架构与模块描述应契合「共享设计系统」的移动端规格——viewport、单栏窄版心、触摸友好字号、深色高对比、首屏结论、禁横向滚动。
- 规格的内容排布遵循 `../SKILL.md`「内容设计指导」:板块分层直观、图表配结论、重点单独成块、密度克制。
- 规格须保留纪律措辞位:参考位"非下单指令"、对称情景双向、短期机会与中长期持仓分栏、风险提示与免责声明——这些位置在生成时由数据源内容填充,但结构要在规格里预留。
- 规格文档不贴大段 HTML/CSS 代码;HTML 结构由 skill 生成时按规格描述构建,样式复用共享设计系统。
