# A股复盘数据看板(移动端HTML渲染)

## 适用边界(Scope)

本skill遵守 `references/boundaries.md` 的全部共享边界,正文不再逐条复述。以下仅列本skill特有边界:

1. **这是"展示层",不是"分析层"**:本skill把用户引用的已有报告/数据内容渲染成移动端HTML看板。它不取实时行情、不跑技术引擎、不做新的买卖推导——看板里出现的每一项结论与数字,都必须能在用户引用的数据源内容里找到出处,绝不凭空生成或外推。
2. **数据缺失按规格规则处理,不编造**:数据源里缺失的字段(如某指数成交额为"—"、某指标未算出),严格按规格文档里规定的"数据缺失处理逻辑"渲染(占位符 / 灰显 / "数据缺失"标注 / 整块降级等),不得用估算值或编造数字填满。这与 `boundaries.md` §7"不编造数字"一致。
3. **忠实呈现,不二次解读**:看板是数据源内容的可视化复刻,不改变其口径与结论。原文里"对称条件式情景"仍双向列出、参考位仍标注"非下单指令"、短期机会与中长期持仓仍分栏——这些纪律在渲染时原样保留,不得为了"好看"改成单边预测或合并口径(§1/§2/§3/§7)。
4. **移动端优先**:输出HTML针对手机竖屏阅读优化——viewport、单栏/窄栏布局、可触摸点击的字号与间距、深色/高对比配色、首屏即核心结论。可在大屏自适应展开,但不以PC宽屏为首要目标。
5. **不预设报告类型、不内置映射表**:本skill默认不知道有哪些报告类型,也不维护"报告类型→数据源路径/规格文件"的映射。用哪份规格、数据源是什么,完全由"用户提示词 + 提示词引用的内容 + `.claude/skills/ashare-dashboard/templates/` 下已存在的规格文档"三者动态结合来判断(见下文工作流)。`.claude/skills/ashare-dashboard/templates/` 为空或无匹配规格时,提示用户放置/创建规格文档,不要硬套不相关规格或凭空自创架构。
6. **规格文档是"指导性描述",不是"可填空模板"**:规格文档用文字描述看板应有的架构、模块、组件、样式与缺失处理规则,不提供现成HTML骨架。生成时由 skill 按规格描述 + 本 SKILL.md 的「共享设计系统」自行构建HTML结构。同一份规格每次生成的看板在架构/分区顺序/样式上必须一致——要改呈现就改规格文档,不要在生成时临时自创架构导致同一规格每次长得不一样。

## 工作流程

### 步骤0:理解用户提示词与引用内容
从提示词中提取:
- 用户想渲染的对象(描述了哪份报告/哪类数据);
- 是否显式引用了数据源——一个文件路径、一段粘贴的报告正文,或仅口头描述;
- 是否点名了某个规格(如"用 XX 规格")。

若提示词未引用任何具体内容、且无法据此定位数据源,向用户确认:请提供报告文件路径或粘贴报告正文。**不要凭"报告类型"猜一个写死的路径**。

### 步骤1:扫描并读取已存在的规格文档
列出 `.claude/skills/ashare-dashboard/templates/` 下所有 `*.md`(忽略 `README.md` 等非规格文件),逐个读取其 frontmatter 自描述(`name` / `match` / `target` / `data`)与正文的架构/模块/样式描述,建立"可用规格 → 各自面向什么"的清单。

- `.claude/skills/ashare-dashboard/templates/` 为空或无任何规格文档 → 如实告知用户尚未放置规格,提示按 `.claude/skills/ashare-dashboard/templates/README.md` 契约创建,停止。

### 步骤2:匹配规格文档
用步骤0的"提示词 + 引用内容"与步骤1的"可用规格自描述"做匹配,选出最贴合的规格:
- 用户显式点名某规格 → 直接用该规格(若不存在则告知)。
- 未点名 → 按 frontmatter 的 `match` 关键词 / `target` 面向数据,选与引用内容最相符的规格;多个同样贴切时向用户确认,不要替用户拍板。
- 无任何规格能合理匹配 → 告知用户当前 `.claude/skills/ashare-dashboard/templates/` 下无合适规格,提示创建,不要硬套一个不相关的规格。

### 步骤3:定位并读取数据源
数据源来自用户引用的内容,不查写死的路径表:
- 用户给了文件路径 → 读取该文件(Markdown 报告 / JSON 等),完整通读,梳理可渲染单元(章节、表格、卡片、情景、消息分组、观察清单等)及顶部"数据源说明"备注(标注哪些是精确值、哪些是定性/未核对)。
- 用户粘贴了正文 → 以粘贴内容为数据源,同样梳理可渲染单元。
- 用户仅口头描述、未给路径或正文 → 向用户索要文件路径或正文,不要假设路径。
- 引用的文件不存在或内容为空 → 如实告知,停止。

### 步骤4:数据绑定(数据源 → 规格模块)
把步骤3梳理出的数据,按步骤2规格文档的模块描述逐一绑定:每个模块对应数据源里的哪个章节/表格/字段,以规格规定的展示形式落地。绑定过程遵守:
- **只搬不造**:只填数据源里真实存在的数据;没有的字段触发该模块的"数据缺失处理逻辑",不外推、不估算、不抄别处数字顶替。
- **口径不变**:涨跌方向、百分比、参考位标注("非下单指令")、分栏(短期机会 vs 中长期持仓)、对称情景双向等,与原文一致,不因排版改动口径。
- **数字精度**:沿用原文精度,不做四舍五入放大或伪精确(原文写"约6,601亿"就照搬,不改成"6,601.00亿")。

### 步骤5:生成移动端HTML看板
以匹配规格文档描述的架构/模块/组件/样式为指导,结合本 SKILL.md 的「共享设计系统」(见下文),把步骤4绑定的数据渲染成一份独立的单文件HTML:
- **移动端优先**:`<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">`;主体单栏、最大宽度 ≤520px 居中,手机竖屏首屏即见核心结论;字号与点击区间满足触摸操作;深色高对比配色便于夜间阅读。
- **自包含**:CSS内联、不依赖本地额外资源(可引用 Google Fonts 等公共CDN字体,与规格保持一致);图标优先用内联SVG或emoji,保证单文件可离线打开。
- **邮件兼容(不依赖 JS)**:看板常经邮件发送,邮件客户端会删除 `<script>` 且不执行 JS。生成的 HTML **不得包含 `<script>`,不得依赖 JavaScript 渲染任何视觉**。所有比例条/柱状图(涨跌家数条、资金分流条、板块涨跌条、温度计距离条、热力条等)的宽度或填色状态**必须在生成时按「共享设计系统」的规则预算并内联到 `style` 或 `class`**,不得留待运行时计算。字体 `<link>` 在邮件中会被剥离 → 须确保 CSS 变量 fallback 字体栈完整(规格与共享设计系统已含 PingFang/Microsoft YaHei/serif/monospace),退化后仍可读;emoji 仅作装饰、不得作传达关键信息的唯一手段(部分客户端会剥离 emoji),关键状态须文字+颜色双编码。
- **缺失处理落地**:凡数据源缺失的字段,按规格文档"数据缺失处理逻辑"渲染占位(如"—"、"数据缺失"灰显、或该卡片标注"本次未提供"),绝不在HTML里塞入数据源里没有的数字。
- **顶部数据源说明**:把数据源里的"数据源说明"备注以小字呈现在看板顶部或底部,如实标注哪些是精确值、哪些是定性/未核对,与原文一致。若数据源报告末尾包含"### 数据来源"表格,将其渲染为看板的"数据来源"区块,保留工具名可溯源。
- **保留纪律措辞**:参考位"非下单指令"、对称情景双向、风险提示与免责声明等,在对应模块原样保留,不得为版面精简而删除。

### 步骤6:输出保存
完成渲染后,把HTML单文件落盘保存到 `output/ashare-dashboard/` 文件夹下,文件名由"匹配到的规格文档"派生:`<规格文件名主干>_dashboard_[日期].html`(规格文件名主干即匹配到的规格文档去掉 `.md` 后缀;日期取运行当天,格式 `YYYY-MM-DD`,与各复盘技能报告 md 的日期口径一致)。文件夹不存在则先创建,同名文件已存在时直接覆盖(同一天重复生成以最新一次为准)。除落盘外,在对话中给出文件路径,并可贴出看板首屏结构示意供用户确认。

## 共享设计系统

所有看板共用同一套基础设计系统。生成HTML时,以匹配规格文档描述的架构/模块为指导,以本节为样式基底;规格文档只写本看板**额外**或**偏离**共享系统的部分。

风险体检看板额外使用四档风险专用色(其他看板不用):
```css
--rk-low:#16C784; --rk-low-soft:rgba(22,199,132,.16);       /* 低=绿 */
--rk-mid:#F0B429; --rk-mid-soft:rgba(240,180,41,.16);       /* 中=黄 */
```

### 字体栈

```css
--fd:'Noto Serif SC',serif;                                              /* 衬线,标题/大字 */
--fb:'Noto Sans SC','PingFang SC','Microsoft YaHei',-apple-system,sans-serif; /* 无衬线,正文 */
--fm:'JetBrains Mono',ui-monospace,monospace;                            /* 等宽,数字 */
```

`<link>` 引 Google Fonts CDN;邮件客户端剥离 `<link>` 时 fallback 到 PingFang/Microsoft YaHei/serif/monospace,退化后仍可读。数字一律用 `font-family:var(--fm); font-feature-settings:"tnum"` 等宽对齐。

### 移动端规格

- `<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">` 必含。
- `body` `max-width:520px; margin:0 auto;` 单栏居中;`font-size:15px; line-height:1.65;`。
- `padding:calc(env(safe-area-inset-top) + 12px) 14px calc(env(safe-area-inset-bottom) + 28px);` 适配刘海与底部手势条。
- 正文 ≥15px,标签/辅助小字 ≥11px;核心大数字 21–32px。可点击元素热区 ≥44×44px。
- 首屏不放占满屏的标题 banner;首屏即给核心结论 / 总览数字。
- 表格、图表宽度自适应屏宽;长表格转卡片列表或横向条形,不在移动端塞整屏表格;超长数字用千分位/亿/万缩写。
- 断点:多数看板用 `@media (min-width:480px){ .kpi-row{grid-template-columns:repeat(3,1fr);} }`(宽屏 KPI 三列);风险体检的"系统性 vs 非系统性"两栏在窄屏用 `@media (max-width:380px){ ... }` 堆叠为单栏。其余不依赖 @media 切换视图。

### 比例条三规则(组内 M = max|v|)

所有比例条/柱状图的宽度**必须在生成时预算并内联到 `style`**,不依赖 `<script>`(邮件客户端会删除且不执行 JS):

1. **分段比例**(涨跌家数三段 span 等):`width = v / Σv × 100%`。
2. **中心零轴半幅**(资金分流条、指数周涨跌分化条等):`S = M×1.15, half = min(50, |v|/S×50);` `v≥0 → left:50%, width:half%;` `v<0 → left:(50-half)%, width:half%。`
3. **单向归一**(板块涨跌条、行业占比条等):`S = M×1.1, width = |v|/S×100%。`

非比例类的离散填色(如风险体检六层热力条的四段)按当前等级在生成时内联 `class`(当前段 on + 配色 class,其余灰),同样不依赖 script。

### 内容设计指导

- **信息分层**:按「总览结论 → 细分数据 → 辅助信息」三层从上到下排;每个板块有明确标题 + 一句话定位;板块间用卡片/留白/分隔线划清边界,一张卡片只讲一件事。
- **图表配结论**:每张图表紧跟一行"一句话结论"(takeaway),点出趋势/拐点/异常;趋势类用「迷你 sparkline + 当日数值 + 涨跌幅」三件套;对比类用横向条形 + 数值标注;图表高度受控(约 60–120px)。
- **重点突出**:核心结论与关键数字用大字号 + 强调色 + 首屏位置;纪律措辞(参考位"非下单指令"、对称情景双向、风险提示)用独立弱化样式(小字 + 灰/边框)与数据区分。
- **密度克制**:单屏 3–5 个信息单元;长列表取 Top N + 折叠/查看更多;表格转卡片或横向条,非要表格则只留 3–4 列。

## 贯穿全程的原则

- **展示层本分**:看板是数据源的镜子,不是新的分析。任何看板里的数字/结论都要能回溯到用户引用的内容;数据源里没有的不补、不猜、不编。
- **动态匹配,不查表**:用哪份规格、数据源在哪,由"提示词 + 引用内容 + 已存在规格文档的自描述"动态判断;skill 不预设报告类型、不内置映射表。要改呈现就改规格文档,不要在生成时临时自创架构导致同一规格每次长得不一样。
- **移动端体验**:手机竖屏、单栏、首屏结论、深色高对比、触摸友好、单文件自包含可离线打开。
- **诚实标注缺失**:数据缺失按规格规则显式占位,不掩盖、不补全。
- **规格文档不得出现真实股票名称**:规格文档中所有示例数据必须使用虚构名称与代码,严禁出现真实A股/港股/美股标的。详细规则见 `templates/README.md`「约定」。
- **无 JS 依赖**:看板是静态 HTML,任何视觉宽度/状态在生成时即确定,不靠运行时脚本(邮件客户端会删 `<script>`)。
